## Result and exact coverage

Fénix now has **171 original skills**: four new workflows and thirteen improved existing entries. Fourteen new references add conditional detail, and one original offline backup-manifest comparator provides a concrete executable check. No upstream skill body, code, asset, installer or dependency was imported or executed. These changes improve procedural coverage and evidence handling; they do not establish general model superiority or automatically strengthen runtime isolation.

The inventory parses metadata and hashes all **818 `SKILL.md` files**. Detailed manual inspection covers **30 selected skills: 18 complete entrypoints and 12 documented sections**, plus **eight Python helpers: six complete and two by section**. The manifest records source paths, line ranges, hashes and pinned URLs. Inventory, download, complete reading and section reading are distinct states. No complete audit of 818 skills, 1096 Python helpers or their dependency trees is claimed.

Selection focused on this assistant's concrete needs: tenant authorization, agent/RAG/MCP trust, document handling, vulnerabilities, supply chain, CI, cloud incidents, backups, tokens, containers and network evidence. Firmware, industrial systems, wireless testing, blockchain, specialized enterprise products and offensive campaign infrastructure remain cataloged but not deeply assessed here. Their prerequisites and deliverables do not justify hundreds of additional generic assistant skills without an actual workload. They can be revisited when requested.

## Findings that changed our implementation

| Upstream mechanism inspected | Finding and retained value | Fénix decision |
| --- | --- | --- |
| Agent tool invocation, RAG injection and vector weaknesses | Per-call identity, tool boundaries and two-tenant tests are useful. The RAG helper sends probes as user messages and labels responses from common words; its cosine threshold does not establish actual retrieval. The policy CLI accepts an actor argument and offers test auto-approval, so its output alone cannot prove runtime identity enforcement. | New `agent-security-evaluation` requires actual lower-trust exposure, server-owned identities, recorded effects, benign controls and separate inconclusive results. No mandatory NeMo/proxy installation or blanket approval prompts. |
| BOLA, mass assignment and WebSocket tests | Paired accounts, protected properties and post-handshake checks are useful. Some examples classify HTTP success alone as a vulnerability; the expired-token WebSocket example catches general exceptions as secure. Echoed fields and network failures do not establish permission behavior. | New `api-security-testing` verifies policy, returned data, independently observed state, partial effects and revocation. Uses disposable resources and bounded tests. |
| SSVC, KEV prioritization, aging and exceptions | Asset context, owners and expiry are useful. SSVC examples infer a PoC from EPSS, use different simplified decision trees and assign fixed example timelines. Missing feed data can become no exploitation. | New `vulnerability-management` separates probability, observed exploitation, applicability and missing data; preserves first-seen dates and verifies closure. Uses a named authoritative SSVC model when requested, never a mislabeled shortcut. |
| PDF and Office macro analysis | Object graphs, macro streams and external relationships improve triage. Static parsing and decoding need their own isolation; macros are not the only active-content path. | New `security-artifact-triage` preserves hashes, limits extraction, records encrypted/unparsed content and avoids automatic preview, emulation or public uploads. |
| SBOM and build provenance | Package identities and expected signer/source are valuable. The SBOM helper loses CycloneDX `bom-ref` identity, processes keyword candidates as CVEs and returns empty results on lookup errors. The provenance helper can report verified after a decoding exception; a documentation command allows any certificate identity. | Extend `dependency-and-secret-audit` with graph identity, coverage, applicability, exact artifact digest and separate cryptographic/policy verification. A parser failure cannot pass. |
| Backup integrity and immutable storage | Restore drills and deletion resistance are useful. The backup helper can pass without a baseline, compare identical error placeholders as equality and write temporary metadata into the restored tree. | Extend `backup-and-restore`; add a strict read-only manifest comparator. Require snapshot consistency and application-level recovery separately. Do not infer malware absence from entropy or extensions. |
| GitHub Actions | Permissions, untrusted event text and artifact promotion are useful review boundaries. Environment names and secret masking alone do not demonstrate configured protection. | Extend `release-and-ci` for fork/workflow/cache trust, actual environment settings and verified promotion. |
| Container hardening and Kubernetes RBAC | Runtime privileges, mounts, admission and escalation paths are useful. Removing shells/package managers indiscriminately would break an assistant workspace. A risk configuration is not an observed escape. | Extend `container-workflows` and `kubernetes-operations`, preserving required workloads and validating effective controls rather than labels/YAML. |
| OAuth consent, service-account rotation and JWT | Owner/consumer mapping and token trust are useful. Secret rotation, grant revocation and session invalidation are distinct. | Extend `identity-access-review` and `authentication-integration`; test issuer/audience, trusted keys, rollover, derived sessions and two-account boundaries. |
| BEC and suspicious consent | Legitimate accounts and authenticated mail can still carry fraudulent payment changes. | Extend `phishing-triage` with trusted header interpretation, QR decoding and independent payment-detail verification. No automatic contact or payment changes. |
| Cloud incidents, traffic analysis and hunting | Identity chains, acquisition windows and corroboration improve investigation. Indicators, periodic traffic and absent logs have limited evidentiary meaning. | Extend `incident-response` and `detection-engineering` with data gaps, falsifiable hypotheses and separate containment/recovery checks. |
| Crypto audit and TLS lifecycle | Primitive purpose, key lifecycle and actual served certificates matter more than keyword flags. | Extend `security-code-review` and `network-diagnostics` with nonce/key trust and issuance/deployment/handshake distinctions. |
| RAG evaluation | Similarity-based examples can overclaim reconstruction or membership, and an admin database query is a different exposure from a user-facing API. | Extend `rag-evaluation` to preserve those distinctions and route adversarial trials to the dedicated skill. |

These are source-level findings about the inspected examples, not results of running upstream software. In particular, the provenance helper's CLI may verify the attestation signature while still failing to establish the expected source/build policy; the report does not claim every signature check is broken.

Primary checks: [FIRST defines EPSS as exploitation probability](https://www.first.org/epss/), [CERT/CC maintains SSVC models](https://certcc.github.io/SSVC/), [OWASP describes object-level authorization](https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization/), [SLSA separates artifact/provenance verification and policy](https://slsa.dev/spec/v1.2/verifying-artifacts), and [JWT BCP](https://www.rfc-editor.org/rfc/rfc8725) / [OAuth BCP](https://www.rfc-editor.org/rfc/rfc9700) inform token boundaries. A direct request for the CISA SSVC page failed during research; no content from that failed fetch is treated as read evidence.

## Original implementation

The new skills are [agent-security-evaluation](../../resources/skills/agent-security-evaluation/SKILL.md), [api-security-testing](../../resources/skills/api-security-testing/SKILL.md), [vulnerability-management](../../resources/skills/vulnerability-management/SKILL.md) and [security-artifact-triage](../../resources/skills/security-artifact-triage/SKILL.md). Their descriptions and bilingual aliases distinguish evaluation, API tests, ongoing remediation and static artifact work from existing implementation/review/document tasks.

The [backup comparator](../../resources/skills/backup-and-restore/scripts/compare_manifests.py) accepts two documented Fénix JSON manifests. It reads at most 8 MiB per input, rejects duplicate keys, invalid hashes, ambiguous paths and incompatible snapshots, and preserves missing/added/changed files and evidence gaps. It writes only its JSON result to stdout, never the restored directory. An empty or incomplete matching inventory is inconclusive. It does not collect files, inspect permissions, detect malware, validate the truth of a manifest or prove application recovery.

## Validation and deployment boundary

Thirty-nine bilingual retrieval cases were saved before edits: twelve new-workflow queries, seventeen existing-workflow queries and ten neighboring-task guards. Baseline comparisons restore the thirteen exact pre-edit bodies and disable the four additions. These are development cases, not a held-out model benchmark. Their recorded outcomes and test summaries are in the evidence JSON.

Validation covers package metadata and relative links; native search, installation, on-demand resources, historical-body upgrade and preservation of custom text/disabled state; and eleven executable comparator tests including invalid/incomplete evidence and CLI exit codes. Test failures and corrections, if any, remain in the recorded validation history.

Final results: **29/29 native skill tests passed**, **80/80 Python helper tests passed** (including eleven new comparator tests), and **17/17 affected packages passed the skill-creator validator**. Rust formatting, local resource links and diff whitespace checks passed. The expected result appears in the top three for **39/39** new development queries (**37/39** in first position). Existing-skill queries improve from **23/27 to 27/27** in the top three; the twelve new-workflow queries pass **12/12**, and all ten neighboring-task guards pass. The first candidate failed two retrieval regressions (ordinary PDF creation and a Spanish source-review query); narrower artifact wording and explicit review aliases corrected both without changing the queries. The historical retrieval suites also pass.

Cargo bundles the new skills/resources into the next build. On startup, new skills are installed, and only exact known historical `SKILL.md` bodies are updated. Thirteen pre-edit fixtures/hashes were retained. Existing custom bodies and enabled state are preserved; existing references retain the runtime's no-overwrite policy. New detail therefore uses new reference paths. The public service was not restarted or deployed, and private user skill directories were not altered.

No live model adversarial campaign, external authenticated scanner, malware execution, production penetration test or new runtime-isolation assessment ran in this iteration. Passing structural, retrieval and helper tests does not establish that the agent is immune to attacks. The benefit demonstrated here is added task coverage, executable manifest behavior and compatibility with Fénix's skill lifecycle.
