# Agent-authored diagrams

Fénix diagrams are read-only in the web interface. Users zoom, pan (mouse or touch), fit the drawing, enter fullscreen, download SVG/source and inspect structured nodes and their references. All content changes, including restoring a historical version, are requested in chat. Other design formats retain their existing editing controls.

## Authoring and storage

`design_publish` accepts either a versioned `content.graph` (nodes, edges, flat groups, direction, node details/references) or `content.source` (Mermaid). The native Rust compiler validates structured relationships and generates Mermaid deterministically. Browser rendering is local, lazy-loaded and sanitized. Existing Mermaid templates remain supported, including sequences and entity diagrams.

`design_read` returns current or historical content. `diagram_edit` applies a batch of ID-based operations with `expected_revision`; invalid endpoints, duplicate IDs, unknown groups and stale revisions are rejected. Full replacements use `design_publish`. The UI's direct update endpoint rejects changes to/from diagram artifacts, so the diagram source view is read-only and has no Save/Restore mutation buttons.

Each user's runtime data directory contains:

```text
diagrams/
  <design-id>/
    v000001.json
    v000001.mmd
    v000002.json
    v000002.mmd
```

For the isolated account layout this is `<user-root>/state/diagrams/`. Standalone installations use `<data-dir>/diagrams/`. IDs are generated by the engine; titles never become directory paths. Snapshot JSON includes the title, graph/source, project, task and revision. Tool receipts return exact paths. Existing diagrams are archived when read through the detail API or agent tool. Revisions created subsequently are archived at save time.

The database remains authoritative for published revisions. Files are durably written before committing a new database revision. If file persistence fails, the old database revision remains current. A crash between file writes and database commit can leave an uncommitted file; it is not exposed as a published revision. Repeating the save can replace that uncommitted snapshot. Editing snapshot files directly does not update the application. Symlink/hard-link traversal uses the existing descriptor-relative filesystem boundary.

## Viewer behavior and scope

The viewer has no node dragging, edge editing, code editing or other content mutation controls. Pointer movement changes only the camera. Zoom, navigation, search, references and downloads do not call an LLM. Keyboard controls: +/− zoom, arrows pan, 0/Home fit. The existing responsive right panel and collapsed sidebar remain in place.

Structured diagrams expose a searchable textual outline, node details and incoming/outgoing connections. Plain Mermaid retains visual navigation and source inspection. Updates keep the last successfully rendered SVG on screen until the next render succeeds; a failure identifies that the previous revision is being shown. This is an in-memory viewer fallback, not a permanent designation of a validated DB revision. Reloading an invalid latest diagram may require selecting an older revision.

Validation checks the structured model, not the truth of its claims. Raw Mermaid syntax is checked by the browser renderer. No external diagram service, Electron application, collaboration framework or Python/Manim runtime is introduced. Advanced animated videos remain a separate future capability; this change delivers navigable diagrams and agent editing.
