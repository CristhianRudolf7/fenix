# Git Recovery And Change Management

## Procedure

Inspect status and diff before making changes. Distinguish tracked edits, untracked files, staged work and branch history. Recover required content from explicit commits, reflogs or object references without overwriting unrelated work. Review resulting diffs and verify the requested files and behavior. Do not publish recovered secrets, raw credentials or private traces. Commit only intended changes with a clear English message and report the actual branch and commit. Destructive reset or cleanup is not a routine recovery method.

## Evidence and scope

Use task-local observed outputs as evidence. This is a manually curated procedure, not a validated benchmark solution. Consult current project instructions. Tool availability and owner permissions take precedence; report missing capabilities.
